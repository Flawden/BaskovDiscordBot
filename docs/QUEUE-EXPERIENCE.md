# Queue Experience

Начиная с `v0.5.0`, музыкальная очередь хранит не только `AudioTrack`, но и данные пользователя, который заказал трек.
Это позволяет показывать requester, прогноз старта и управлять ожидающими треками без остановки текущей песни.

В `v0.10.0` очередь получила постраничную навигацию по 10 позиций, глобальные номера треков и отдельный ETA старта для каждой строки.

В `v1.2.0` добавлен Queue Manager 2.0: monotonic ревизия ожидающей очереди, stale-safe batch mutations, удаление диапазона, dedupe и self-service очистка собственных ожидающих треков.

В `v1.9.0` поверх requester identity добавлен collaboration layer: просмотр только своих позиций, ownership-safe удаление одного своего трека, вклад заказчиков и read-only vote-skip status.

## Slash-команды

| Команда | Назначение |
|---|---|
| `/previous` | Возвращает последний завершённый или пропущенный трек; текущий ставит первым в очередь |
| `/queue [page]` | Текущий трек, выбранная страница из 10 позиций, requester, ETA каждой строки, громкость и repeat mode |
| `/remove position` | Удаляет ожидающий трек по номеру из `/queue` |
| `/move from to` | Перемещает ожидающий трек между позициями |
| `/shuffle` | Перемешивает только ожидающие треки |
| `/clear` | Очищает ожидающие треки, но не прерывает текущий |
| `/queue-manage stats` | Показывает размер, длительность, заказчиков, дубликаты и текущую ревизию |
| `/queue-manage mine` | Показывает собственные ожидающие треки с глобальными позициями и ревизией |
| `/queue-manage community` | Показывает вклад requester-ов: число треков, длительность и позиции |
| `/queue-manage remove-own position [revision]` | Удаляет одну позицию только если её requester — автор команды |
| `/queue-manage remove-range start end [revision]` | Атомарно удаляет непрерывный диапазон ожидающих позиций |
| `/queue-manage dedupe [revision]` | Удаляет повторные копии, сохраняя первую позицию каждого трека |
| `/queue-manage remove-mine [revision]` | Удаляет только ожидающие треки автора команды |
| `/volume level` | Устанавливает громкость от 0 до настроенного максимума |
| `/repeat mode` | `off`, `track` или `queue` |

Все общие изменяющие команды проходят `MusicControlPolicy`: обычный участник должен находиться в том же voice channel, что и бот. Владелец сервера и участник с `Manage Server` сохраняют административный override. Исключения — `/queue-manage remove-own` и `remove-mine`: они могут удалить только позиции с requester user ID самого автора команды и поэтому не дают управления чужой очередью. Для `remove-own` stale revision проверяется до ownership-check.


## Ревизия и batch mutations

Каждое изменение waiting queue увеличивает session-local revision: добавление ожидающего трека, переход к следующему, previous с возвратом текущего трека в начало, remove/move/shuffle/clear и операции Queue Manager. Ревизия начинается заново после создания новой runtime-сессии и не является persistence ID.

`/queue` и `/queue-manage stats` показывают текущую ревизию. Если передать её как `revision` в mutating subcommand, `TrackScheduler` проверит revision внутри того же mutation lock, что и само изменение. Несовпадение возвращает stale-result без удаления треков. Это защищает от ситуации, когда пользователь посмотрел позиции, а до отправки команды очередь уже успела сдвинуться.

`dedupe` сравнивает стабильный media identifier; если он недоступен, использует URI, затем metadata fallback. Операция явная: повторные треки разрешены обычным `/play`, а удаляются только по запросу Queue Manager.

## Requester и ETA

Для каждого добавленного трека сохраняются:

- Discord user ID;
- отображаемое имя на момент заказа;
- время добавления;
- исходный `AudioTrack`.

Ответ `/play` показывает requester, позицию и приблизительное время до старта. `/queue` повторяет расчёт отдельно для каждой видимой позиции. ETA рассчитывается из остатка текущего трека и длительности уже ожидающих треков. Это прогноз, а не гарантия: skip, seek, remove, shuffle и сетевые ошибки меняют фактическое время.

## Страницы и кнопки

- `/queue` открывает первую страницу;
- `/queue page:3` сразу показывает третью страницу;
- кнопки `◀ Назад` и `Вперёд ▶` редактируют то же сообщение и не создают поток новых ответов;
- номер позиции остаётся глобальным для всей очереди, поэтому его можно напрямую использовать в `/remove position` и `/move from to`;
- запрос страницы за пределами очереди безопасно переводится на последнюю доступную страницу;
- навигация read-only и не требует права управления активным voice-сеансом;
- `👤 Мои треки` открывает requester-filtered список с теми же глобальными позициями;
- `👥 Заказчики` показывает вклад участников в waiting queue;
- `🗳️ Vote skip` показывает `votes/required`, threshold и состояние собственного голоса, но сам голос не отдаёт.

`/now` и блок текущего трека в `/queue` показывают визуальную шкалу прогресса, позицию и оставшееся время.

## Повтор

- `off` — обычное воспроизведение;
- `track` — после естественного завершения повторяется текущий трек;
- `queue` — завершившийся трек добавляется в конец очереди.

Кнопка `Повтор` циклически переключает `off → track → queue → off`.
Ручной skip не считается естественным завершением и не заставляет пропущенный трек повторяться. При этом трек попадает в bounded history и доступен через `/previous`.

## Громкость

Новая сессия получает `DISCORD_BOT_MUSIC_DEFAULT_VOLUME`. `/volume` ограничен значением `DISCORD_BOT_MUSIC_MAX_VOLUME`.

```text
DISCORD_BOT_MUSIC_DEFAULT_VOLUME=100
DISCORD_BOT_MUSIC_MAX_VOLUME=150
```

Границы:

- default volume: от 0 до max volume;
- max volume: от 1 до 500.

Громкость и repeat mode по умолчанию сохраняются между перезапусками через guild-настройки.
