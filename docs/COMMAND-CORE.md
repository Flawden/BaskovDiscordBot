# Command Core v0.2

## Поток обработки

1. JDA передаёт `MessageReceivedEvent` в `BotEvents`.
2. Сообщения ботов, webhook, DM и неподдерживаемых каналов игнорируются.
3. `CommandInvocation` разбирает имя команды и аргументы без сохранения Discord event в поле класса.
4. `CommandRegistry` выполняет case-insensitive lookup команды.
5. Dispatcher проверяет owner-only ограничение и cooldown.
6. Для одного вызова создаётся неизменяемый `EventArgs`.
7. Необработанная ошибка команды логируется, а пользователю отправляется нейтральное сообщение без stack trace.

## Контракт команды

Каждая команда реализует `Event` и обязана предоставить:

- `getName()` — уникальное ASCII-имя без пробелов;
- `getGroup()` — группу для `!help`;
- `helpMessage()` — короткое описание;
- `needOwner()` — owner-only флаг;
- `execute(EventArgs)` — выполнение;
- при необходимости `cooldown()`.

Имена проверяются при старте. Два имени, отличающиеся только регистром, считаются дубликатами и останавливают запуск.

## Аргументы

Новый API:

- `getArguments()` — неизменяемый список токенов без имени команды;
- `getRawArguments()` — исходная строка после имени команды;
- `getArgs()` — compatibility API, где индекс 0 содержит введённую команду.

Для поисковых запросов и текста с пробелами следует использовать `getRawArguments()`.

## Безопасность media URL

`MediaQueryResolver` не открывает ссылку для проверки. Он принимает только HTTP/HTTPS URL доверенных доменов SoundCloud/YouTube. Любые `file://`, loopback, внутренние и произвольные хосты отклоняются до передачи в LavaPlayer. Локальный файловый source LavaPlayer отключён.
