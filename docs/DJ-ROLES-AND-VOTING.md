# DJ-роли и голосование за пропуск

Начиная с `v0.14.0`, каждый Discord-сервер может отдельно настроить,
кто управляет активной музыкальной сессией. Настройки хранятся в уже
существующем `guild-settings.properties` и переживают restart/redeploy.

## Режимы доступа

### `open`

Режим по умолчанию и полная обратная совместимость. Любой обычный участник
может управлять музыкой, если находится в том же voice channel, что и бот.
Владелец сервера и участники с `Manage Server` сохраняют административный
override.

```text
/settings access mode:open
```

### `dj`

Прямые команды playback доступны:

- владельцу сервера;
- участникам с `Manage Server`;
- участникам настроенной DJ-роли, находящимся в voice channel бота.

Остальные слушатели могут добавлять музыку через `/play`, `/search`,
`/playlist play` и `/replay`, но не могут менять текущий playback.

```text
/settings dj-role role:@DJ
/settings access mode:dj
```

Если включить режим `dj` без назначенной роли, прямое управление останется
только у владельца и `Manage Server`.

### `vote`

DJ и администраторы управляют playback напрямую. Обычные слушатели могут
голосовать за пропуск текущего трека:

```text
/voteskip
/skip
```

Кнопка `Следующий` под `/now` использует ту же логику: для DJ это прямой
пропуск, для обычного слушателя — голос.

Другие опасные команды (`stop`, `seek`, `previous`, `pause`, `repeat`,
`shuffle`, изменения очереди и громкости) остаются прямыми DJ-командами.

```text
/settings access mode:vote
/settings vote-threshold percent:50
```

## Порог голосования

Порог настраивается от `25` до `100` процентов и по умолчанию равен `50%`.
Требуемое число голосов округляется вверх:

```text
1 слушатель, 50% → 1 голос
3 слушателя, 50% → 2 голоса
5 слушателей, 60% → 3 голоса
```

Учитываются только люди в текущем voice channel бота. Боты исключаются.
Один Discord user может проголосовать за конкретный playback только один раз.

## Жизненный цикл голосов

Голосование привязано к конкретному объекту воспроизведения, а не только к
названию или YouTube URL. Голоса не переносятся на:

- следующий трек;
- повтор того же трека;
- fallback-кандидат;
- новую музыкальную сессию.

На гильдию хранится не более одной vote-session. После достижения порога она
удаляется до запуска следующего трека. Защитный TTL равен шести часам.
`/stop`, смена access mode, DJ-роли, порога или `/settings reset` также
сбрасывают открытое голосование.

## Настройка

Все изменения постоянных правил требуют владельца сервера или `Manage Server`:

```text
/settings show
/settings access mode:open|dj|vote
/settings dj-role role:@DJ
/settings dj-role
/settings vote-threshold percent:50
/settings reset
```

`/settings dj-role` без параметра очищает роль. `@everyone` нельзя назначить
DJ-ролью: для открытого доступа существует отдельный режим `open`.

## Безопасность

- DJ-роль не даёт Discord permissions и не изменяется ботом; проверяется только
  уже существующее членство пользователя в роли.
- DJ без административных прав должен находиться в voice channel бота.
- Владелец и `Manage Server` могут управлять из другого канала, как и раньше.
- Добавление треков остаётся доступным обычным слушателям, чтобы DJ mode не
  превращал музыкальную очередь в закрытый интерфейс.
- Голоса хранятся только в памяти: Discord user IDs не записываются на диск.
